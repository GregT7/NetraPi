53. 54. `CloudIngest.sync_trip_segment` stays JSON-only during the drive. `upload_trip_segment` / `drain_trip_segments` is the Wi‑Fi job: finished local files (`init_local_stored` true, `s3_stored` not true), one at a time, `s3-upload-url` (`trip_segment_id`) + PUT + confirm, then set Pi SQLite `s3_key` / `s3_stored`. Skip PUT if already stored. `POST /trip-segment` retries do not wipe those flags. Edge `main.py --drain-trips` runs the drain without the capture loop.
55. Local media cleanup is a separate Pi job (not the capture loop). `main.py --delete-uploaded-local` unlinks clip/trip MP4s that already have `s3_stored` true. `main.py --delete-all-local` unlinks every finished local clip/trip MP4 (and leftover files in the clips/trips dirs) but does **not** delete S3 objects. Both set `init_local_deleted = true` and clear `local_path` on Pi SQLite after `POST /api/netrapi/confirm-local-delete` updates Postgres. Unfinished recordings (`init_local_stored` not true) are left on disk.

If it matches any stored snapshot (including Alembic seed id 1), reuse that `id` on the driving session and do not insert. If it differs, insert a new snapshot. ~~Edge still loads JSON at startup (decision 27 is not done).~~ `POST /api/netrapi/master-config` is the cloud find-or-create; `CloudIngest.sync_session` calls it first so the FK exists. kNN feature lookup is scoped to that session’s `knn_config`.

62. S3 object keys are `{MMM-YYYY}/driving_session_id_{id}/clips|trips/{clip|trip}-{id}.mp4`, minted only by FastAPI from `driving_session.start_time` (UTC, fixed English `Jan`…`Dec` table so Render/Pi locale cannot emit `août`) and session id. 63. Edge boot health is synchronous before capture. `GET /health` stays cheap liveness (wake Render + in-drive keep-alive). Authenticated `GET /api/netrapi/ready` proves Postgres (`SELECT 1`) and S3 (`HeadBucket`). No Wi-Fi association is an informational offline start. Associated-but-no-internet or failed `/health`/`/ready` is offline fallback with a loud log. Online/offline is one-way for the process: no upgrade to online mid-drive; three consecutive keep-alive failures drop to offline for the rest of the run. Health settings live in `health.json` and are snapshotted as `health_config` (not connectivity mode on `driving_session`). After an offline drive, `--drain-trips {clips,trips,both}` uploads leftovers on Wi-Fi. `--delete-after-drain {clips,trips,both}` may run after a successful drain to unlink the matching local MP4s already in S3 (S3 objects stay). Active plan is TP-01–62.
